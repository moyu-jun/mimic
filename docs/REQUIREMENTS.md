# Mimic 最终需求文档

## 1. 产品定位与范围

Mimic 是一款仅面向 Windows 的桌面按键与鼠标模拟工具，主要用于游戏及其他需要重复输入的场景。

应用应提供以下核心能力：

- 配置并循环执行键盘按键序列。
- 配置并循环执行鼠标点击序列。
- 创建多个具名自定义序列，在同一序列中混合编排键盘与鼠标动作。
- 使用全局启动热键和停止热键控制模拟。
- 管理模拟所依赖的 Interception 驱动。
- 在模拟启动和停止时播放低延迟提示音。
- 使用系统麦克风录制、剪裁并替换提示音。
- 持久化用户配置，并在应用重启后恢复。

当前版本范围限制：

- 项目定位为个人及朋友使用的开源工具，当前不用于商业销售，也不投放应用商店或其他正式分发渠道。
- 当前发布流程不引入商业代码签名、证书购买、证书保管或证书轮换要求；若未来调整分发定位，应另行评审并新增需求。
- 仅支持 Windows，不支持 macOS 和 Linux。
- 按键动作和热键均按单键处理，不支持组合键。
- 不支持方向键、PrintScreen 等白名单之外的按键。
- 鼠标动作界面仅开放左键、中键、右键单击。
- 坐标拾取以单显示器、标准 DPI 缩放为主要支持场景。
- 不提供麦克风设备选择界面。
- 不支持多个模拟序列并发运行。
- 不提供宏录制或自动记录键鼠操作功能。

## 2. 运行环境与权限

### 2.1 驱动依赖

- 键盘热键监听、坐标拾取及键鼠模拟依赖 Interception 驱动。
- 驱动未安装、安装后尚未重启或驱动发生错误时，模拟相关功能不可用。
- 驱动不可用时，应用界面、配置查看和非驱动功能仍必须正常打开和使用。
- 驱动安装并完成系统重启后，普通用户权限下应能正常监听热键和执行模拟。

### 2.2 权限策略

- 应用默认以普通用户权限启动，不得在启动时强制弹出 UAC。
- 启动时应检测当前进程权限，仅用于状态展示，不得因此提升主程序权限。
- 驱动检测及普通模拟不要求管理员权限。
- 安装驱动、卸载驱动和重启电脑属于高权限操作。
- 高权限操作必须通过独立、最小化、经过完整性校验的提权辅助程序执行，主程序不得整体以管理员身份重启。
- 提权辅助程序只能在用户明确点击安装、卸载或重启操作后启动并触发 UAC，不得在应用启动或后台静默触发。
- 主程序与提权辅助程序之间只允许传递预定义操作和必要参数，不得接受任意命令、任意可执行文件路径或任意脚本。
- 用户拒绝 UAC 后，应用应继续保持普通功能可用。

## 3. 应用窗口与全局界面

### 3.1 窗口

- 主窗口固定为 800×600。
- 窗口不可缩放、不可最大化、不可进入全屏，但允许最小化。
- 窗口不使用系统标题栏，由应用提供自定义标题栏。
- 窗口应居中打开，并使用透明背景配合外层圆角。
- 标题栏拖拽区域应支持移动窗口；最小化和关闭按钮区域不得触发拖拽。

### 3.2 标题栏

标题栏应包含：

- 应用图标。
- 应用名称“Mimic”。
- 居中显示的当前页面中文名称。
- 最小化按钮。
- 关闭按钮。

运行状态不得放在标题栏，应统一显示在底部状态栏。

- 窗口标题和页面标题应统一为“Mimic”。
- 标题栏图标、页面图标、可执行文件图标和发布包图标应使用统一的 Mimic 正式品牌图标。

### 3.3 主布局

主界面固定分为：

- 顶部自定义标题栏。
- 中部左侧菜单和右侧页面内容区。
- 底部全局状态栏。

左侧菜单顺序为：

1. 首页。
2. 按键模拟。
3. 鼠标模拟。
4. 自定义。
5. 设置；固定放在菜单底部。

### 3.4 视觉与交互

- 整体采用 Windows 11 风格的深色现代主题。
- 使用深灰背景、中灰容器、浅灰边框和橙色强调色。
- 成功、警告和错误分别使用绿、橙、红等明确状态色。
- 控件应使用统一圆角、柔和边框和微弱阴影。
- hover、active、focus 和页面切换应具有 120～220ms 的过渡反馈。
- 可滚动页面和列表应预留滚动条宽度，避免滚动条出现时内容横向抖动。
- 800×600 窗口下所有文字、按钮、输入框和列表不得溢出或被截断。

## 4. 首页需求

首页应展示应用整体状态，包含：

- 应用名称。
- 当前版本号。
- 应用简要说明。
- 当前管理员权限状态。
- Interception 驱动状态及可执行操作。
- 当前启动热键和停止热键摘要。
- 配置初始化警告或关键错误提示。

### 4.1 权限状态

- 主程序应显示为普通权限运行，不提供“以管理员身份重启”按钮。
- 驱动未安装时，权限提示为“安装驱动时将请求管理员权限”。
- 驱动已安装、已加载或发生错误时，权限提示为“卸载驱动时将请求管理员权限”。
- 用户发起高权限操作后，应显示提权结果；用户取消 UAC 时提示操作已取消，不改变原驱动状态。

### 4.2 驱动状态卡片

驱动卡片应覆盖以下状态：

| 状态 | 展示与操作 |
|---|---|
| 未安装 | 显示“驱动未安装”和“安装驱动”按钮 |
| 已安装待重启 | 显示“驱动已安装，需重启电脑”，提供“重启电脑”和“卸载驱动” |
| 已就绪 | 绿色显示“Interception 驱动已加载”，提供“卸载驱动” |
| 错误 | 红色显示“驱动错误”，并展示可理解的错误提示 |
| 刚卸载待重启 | 显示“驱动已卸载，需重启电脑”，提供“重启电脑” |

- 安装命令成功后应立即显示“已安装待重启”，不得要求驱动在重启前已加载。
- 卸载命令成功后应立即显示“已卸载待重启”。
- 安装或卸载成功应显示明确的绿色反馈。
- 首页内容应支持纵向滚动。

### 4.3 热键摘要

首页应以只读形式显示：

“启动：<启动键> ｜ 停止：<停止键>”

编辑入口位于设置页。

## 5. 按键模拟页面

### 5.1 动作列表

按键模拟页面应提供：

- 按键捕获输入框。
- “添加”按钮。
- 可滚动的按键动作列表。
- 空列表提示。

每个按键动作应包含：

- 启用状态。
- 键位显示名。
- scan code。
- 动作执行后的间隔时间。
- 上移按钮。
- 下移按钮。
- 删除按钮。

### 5.2 添加与编辑

- 用户完成按键捕获后，点击“添加”新增动作。
- 新增按键动作默认不启用，间隔默认为 20ms。
- 同一按键模拟列表中不得存在相同 scan code 的重复动作。
- 添加重复按键时不新增数据，并显示 2 秒自动消失的橙色提示。
- 用户可以启用或禁用任意动作。
- 禁用动作应以降低透明度、灰化等方式与启用动作明显区分，不得使用文字删除线。
- 用户可以通过上移、下移调整执行顺序。
- 第一行动作的上移按钮和最后一行动作的下移按钮应禁用。
- 删除动作后应立即从列表移除。

### 5.3 间隔输入

- 间隔输入仅接受数字，不接受负号和非数字字符。
- 输入过程中允许临时为空。
- 按 Enter 或输入框失焦时提交。
- 空值、0 或无效值提交时恢复为默认 20ms。
- 有效间隔不得小于 5ms；低于 5ms 的值应按 5ms 处理。
- 输入框不得显示浏览器自带的加减步进按钮。
- 数值应在提交时持久化，而不是逐字符写盘。

### 5.4 页面热键

- 按键模拟页面属于可启动模拟页面。
- 页面就绪时状态为 ReadyKeyboard。
- 启动后状态为 RunningKeyboard。

## 6. 鼠标模拟页面

### 6.1 动作列表

鼠标模拟页面应以固定表头的表格展示动作，包含：

- 启用状态。
- 操作类型。
- X 坐标。
- Y 坐标。
- 动作执行后的间隔时间。
- 坐标拾取按钮。
- 删除按钮。

支持的操作类型为：

- 左键单击。
- 中键单击。
- 右键单击。

### 6.2 添加与编辑

- 页面底部应提供“添加”按钮。
- 新增鼠标动作默认启用、类型为左键单击、坐标为空、间隔为 20ms。
- 用户可以启用或禁用动作。
- 禁用动作应与启用动作有明显视觉差异。
- 用户可以修改单击类型、间隔时间和坐标。
- X、Y 坐标不得手动输入，只能通过坐标拾取更新。
- 坐标未设置时显示“—”或等价占位符。
- 间隔输入规则与按键模拟页面一致。
- 删除动作后应立即从列表移除。
- 列表应支持纵向滚动，表头保持可见。

### 6.3 页面热键

- 鼠标模拟页面属于可启动模拟页面。
- 页面就绪时状态为 ReadyMouse。
- 启动后状态为 RunningMouse。

## 7. 自定义序列

### 7.1 自定义列表页

- “自定义”菜单的初始页面为序列卡片列表。
- 第一张卡片固定为新建卡片，以“+”和“新建序列”标识。
- 其余卡片展示序列名称和动作数量。
- 卡片名称过长时应省略显示，并允许用户查看完整名称。
- 点击已有卡片进入对应序列详情。
- 自定义列表页不激活任何序列，启动热键在该页面无效。

### 7.2 新建与命名

- 点击新建卡片后应创建一个空序列并进入详情页。
- 默认名称格式为“未命名序列 N”。
- 默认名称不得与已有序列名称重复。
- 详情页顶部允许直接编辑序列名称。
- 名称在失焦或按 Enter 时提交。
- 名称应去除首尾空白。
- 空名称提交后自动恢复为“未命名序列”。
- 重命名后返回列表应立即展示新名称。

### 7.3 序列详情

序列详情页应提供：

- 返回列表按钮。
- 序列名编辑框。
- 删除整个序列按钮。
- 按键捕获与“添加按键”按钮。
- “添加鼠标”按钮。
- 按顺序显示的动作列表。

每个动作行应包含：

- 启用开关；该位置不再显示额外的“键/鼠”类型标识。
- 对应的键位或鼠标类型与坐标。
- 间隔时间。
- 上移按钮。
- 下移按钮。
- 删除按钮。

### 7.4 自定义动作

- 一个自定义序列可以按任意顺序混排键盘动作和鼠标动作。
- 动作执行顺序必须与详情页中的数组顺序一致。
- 添加键盘动作前必须先完成按键捕获。
- 添加鼠标动作时默认类型为左键单击、坐标为空、间隔为 20ms。
- 自定义鼠标动作支持左键、中键和右键单击。
- 自定义鼠标动作坐标只能通过坐标拾取设置。
- 已有键盘动作允许重新捕获并替换键位；取消捕获时保留原键位。
- 已有鼠标动作允许修改单击类型并重新拾取坐标。
- 不支持将已有键盘动作直接转换为鼠标动作，也不支持将已有鼠标动作直接转换为键盘动作；改变动作种类时应删除原动作后重新添加。
- 用户可以上移、下移或删除动作。
- 用户可以启用或禁用任意自定义动作；新增动作默认启用。
- 禁用动作应明显灰化，并在执行时跳过，但不得删除其参数和排序位置。
- 启用状态变化应立即持久化，并在应用重启后恢复。
- 坐标不完整的鼠标动作应在执行时跳过。
- 序列不存在、序列为空或没有有效动作时，启动热键应被静默忽略。
- 自定义序列、动作和顺序必须持久化。
- 自定义数据与独立按键页、鼠标页数据互不影响。

### 7.5 删除与热键

- 删除入口位于序列详情页。
- 点击删除整个序列时必须显示确认框，明确展示将删除的序列名称和“该操作不可撤销”。
- 用户确认后才删除并持久化，随后返回卡片列表；用户取消时不得修改内存或磁盘数据。
- 删除整个序列不提供撤销功能；删除单个动作行仍立即执行，不额外提供确认框或撤销。
- 进入序列详情后状态为 ReadyCustom，启动热键仅启动当前详情对应序列。
- 自定义序列运行时状态为 RunningCustom。
- 停止后应返回 ReadyCustom，仍可再次启动当前序列。
- 返回列表或切换其他主页面后，应清除当前激活序列。

## 8. 按键捕获与支持范围

### 8.1 捕获交互

- 按键捕获输入框获得焦点后进入捕获状态，并显示“请按下热键”或等价提示。
- 捕获时应阻止默认输入和事件传播，避免触发已注册的全局热键。
- 捕获成功后显示按键名称。
- 未捕获新按键就失焦时，应恢复进入捕获前的原值。
- 白名单之外的按键应静默忽略，并继续等待下一次输入。
- 当前版本每次只捕获一个按键，不识别组合键。

### 8.2 支持键位

支持以下键位作为模拟按键和全局热键：

- A～Z。
- 0～9。
- F1～F12。
- Space。
- Tab。
- Esc。
- Left Shift、Right Shift。
- Left Ctrl、Right Ctrl。
- Left Alt、Right Alt。

Left/Right Shift、Ctrl、Alt 均允许单独配置为启动或停止热键，不要求与其他按键组合。

不支持方向键及其他未列入白名单的键位。

## 9. 全局热键与设置

### 9.1 热键配置

设置页应提供：

- 启动热键捕获输入框。
- 停止热键捕获输入框。
- 独立的保存按钮。
- 保存结果提示。
- 提示音设置区块。

热键配置要求：

- 默认启动热键和停止热键均为 F12。
- 启动热键和停止热键允许配置为同一个按键。
- 两者相同时，待机/就绪状态下按键用于启动，运行状态下按键用于停止。
- 启动热键或停止热键不得与始终可运行的独立按键模拟列表中的任何 scan code 重复。
- 保存热键时发现上述冲突，应拒绝保存并提示“热键与按键模拟列表冲突，请更换”或等价信息。
- 非当前自定义序列允许暂时保存与启动键或停止键相同的按键动作。
- 进入某个自定义序列详情、准备启动或相关配置发生变化时，应校验当前序列与启动键、停止键的冲突。
- 当前自定义序列存在冲突时，应指出冲突动作并阻止该序列启动；不得阻止用户继续编辑、删除冲突动作或离开该序列。
- 保存时应与已持久化热键比较。
- 无变化时静默处理，不显示成功提示，也不重复写盘。
- 有变化时才保存；成功、持久化失败和冲突拒绝应分别显示 2 秒自动消失的提示。
- 保存成功后，首页和状态栏中的热键摘要必须立即刷新。
- 保存按钮宽度应与热键输入框一致，为 140px。

### 9.2 热键生效范围

- 应用必须先加载配置，再使全局热键生效。
- 热键保存成功后，新键位应立即生效，无需重启应用。
- 窗口最小化或失去焦点后，全局热键仍应有效。
- 热键仅在按键模拟页、鼠标模拟页和自定义序列详情页生效。
- 首页、设置页和自定义卡片列表页不得启动或停止模拟。
- 设置页捕获输入框聚焦时，已配置热键只用于输入捕获，不触发模拟。
- 驱动不可用时，全局热键功能不可用，并应在界面中说明原因。

### 9.3 热键去抖

- 同一次物理按键按下只能触发一次启动或停止行为。
- 首次 KeyDown 触发后，应忽略操作系统或驱动产生的重复 KeyDown，直到收到对应 KeyUp 后才允许下一次触发。
- 去抖规则必须同时适用于启动键、停止键以及两者配置为同一按键的场景。

### 9.4 状态门控与透传

- ReadyKeyboard、ReadyMouse 或 ReadyCustom 状态下，仅启动热键可启动对应模拟。
- RunningKeyboard、RunningMouse 或 RunningCustom 状态下，仅停止热键可停止模拟。
- 真正生效的启动或停止热键应由应用消费，不得继续透传到目标程序。
- 状态不匹配的热键应被忽略、不播放提示音，并继续透传到系统。
- 非热键输入应透传到系统。
- 热键捕获输入框聚焦时，捕获到的按键由输入框消费，不执行全局热键行为。
- 模拟运行期间，其他键盘和鼠标输入不得因监听热键而被阻塞。
- 坐标拾取之外的普通鼠标左键应透传到系统。

### 9.5 日志设置

- 设置页应提供日志等级选择控件，选项固定为 Error、Warn、Info、Debug。
- 用户选择后应立即保存并在当前进程即时生效；保存失败时恢复原等级并显示错误。
- 控件应说明发布环境默认等级为 Error，提高等级会产生更多诊断信息和磁盘占用。

## 10. 鼠标坐标拾取

- 用户只能从鼠标动作行或自定义序列中的鼠标动作行发起坐标拾取。
- 进入拾取后，运行状态为 PickingMouse。
- 拾取期间应用窗口必须隐藏，避免遮挡目标位置。
- 用户下一次按下鼠标左键时完成拾取。
- 用于拾取的左键点击必须同时透传给目标窗口。
- 应记录点击时的系统光标屏幕坐标。
- 拾取完成后，应用窗口恢复显示并重新获得焦点。
- 坐标应写回发起拾取的动作行并立即持久化。
- 从独立鼠标页发起拾取时，完成后恢复 ReadyMouse。
- 从自定义序列详情发起拾取时，完成后恢复 ReadyCustom。
- 拾取期间按 Esc 应取消拾取；进入拾取后 30 秒内未完成也应自动取消。
- 取消或超时后应恢复应用窗口、焦点和发起拾取前的 ReadyMouse 或 ReadyCustom 状态，不修改原坐标、不写盘。
- 坐标读取失败时不得写入 (0, 0) 或覆盖原坐标；应恢复窗口和原 Ready 状态，并显示可理解的错误。
- 模拟运行或录音期间不得开始坐标拾取。
- 拾取期间不得切换页面、启动模拟、开始录音或修改运行上下文。
- 坐标拾取应支持普通窗口、无边框全屏和常见独占全屏游戏。
- 游戏主动锁定、隐藏或持续重置系统光标时，不保证拾取坐标准确；用户可切换到窗口化或无边框全屏后重试。
- 多显示器和高 DPI 场景的坐标准确性不作为当前版本保证范围。

## 11. 模拟执行

### 11.1 按键序列

- 启动时只读取启用的按键动作。
- 动作按页面列表顺序执行。
- 每个按键动作应执行一次按下和释放。
- 动作完成后等待该行配置的间隔时间。
- 执行到列表末尾后从第一项重新开始。
- 没有启用动作时，本次启动静默忽略，不改变状态、不显示锁定蒙版、不播放提示音。

### 11.2 鼠标序列

- 启动时只读取启用且 X、Y 坐标均有效的鼠标动作。
- 动作按页面列表顺序执行。
- 每个动作先移动到目标坐标，再执行所选的左键、中键或右键单击。
- 动作完成后等待该行配置的间隔时间。
- 执行到列表末尾后从第一项重新开始。
- 没有有效动作时，本次启动静默忽略，不改变状态、不显示锁定蒙版、不播放提示音。

### 11.3 自定义序列

- 启动时只执行当前激活序列。
- 键盘和鼠标动作必须严格按照详情页顺序串行执行。
- 坐标无效的鼠标动作应跳过，不影响其他动作。
- 每个动作完成后等待该行配置的间隔时间。
- 执行到序列末尾后从第一项重新开始。
- 没有有效动作时静默忽略启动。

### 11.4 启动与停止

- 任意时刻最多只能运行一个模拟任务。
- 模拟应持续循环，直到停止热键或允许的停止操作生效。
- 启动成功后才播放启动提示音并进入对应 Running 状态。
- 停止成功后才播放停止提示音并恢复对应 Ready 状态。
- 停止完成后不得继续产生该任务的输入事件。
- 停止或执行错误时，应用应释放由模拟产生的所有已按下键盘键和鼠标按钮。
- 快速执行“启动 → 停止 → 再启动”时，新任务不得执行上一任务遗留动作。
- 从接收到有效停止请求到停止完成，P95 应不超过 100ms，最坏情况应不超过 250ms；动作间长延时必须可中断并纳入该指标。
- 停止完成的判定必须同时满足：运行任务已终止、模拟产生的按下状态已释放、旧任务不会再产生输入事件、界面已恢复对应 Ready 状态。
- 驱动发送失败时应停止当前模拟、恢复安全输入状态并显示错误。

## 12. 运行状态与交互锁定

### 12.1 状态

应用状态栏应支持以下状态：

| 状态 | 用户含义 |
|---|---|
| Idle | 首页、设置页或自定义列表页处于待机 |
| ReadyKeyboard | 按键模拟页已就绪 |
| ReadyMouse | 鼠标模拟页已就绪 |
| ReadyCustom | 某个自定义序列详情已就绪 |
| RunningKeyboard | 按键序列运行中 |
| RunningMouse | 鼠标序列运行中 |
| RunningCustom | 自定义序列运行中 |
| PickingMouse | 正在拾取鼠标坐标 |
| Recording | 正在录制提示音 |
| Error | 输入驱动、全局监听器或 Runtime 关键错误 |

状态栏左侧应以“状态圆点 + 简短中文文案”展示当前状态：

- Idle 使用中性灰色。
- ReadyKeyboard、ReadyMouse、ReadyCustom 使用中性提示色。
- RunningKeyboard、RunningMouse、RunningCustom 使用绿色。
- PickingMouse、Recording 使用橙色。
- Error 使用红色。

状态栏右侧应实时显示：

“启动：<启动键> ｜ 停止：<停止键>”

### 12.2 页面状态切换

- 进入按键模拟页时切换为 ReadyKeyboard。
- 进入鼠标模拟页时切换为 ReadyMouse。
- 进入自定义卡片列表页时切换为 Idle。
- 进入自定义序列详情时切换为 ReadyCustom。
- 进入首页或设置页时切换为 Idle。
- 按键页和鼠标页可以直接切换，并同步更新 Ready 状态。
- 模拟、坐标拾取或录音进行中不得切换页面。
- CriticalRuntime 导致的 Error 状态只能在错误来源消除并重新检测或重新初始化成功后恢复，不应靠页面切换掩盖。

### 12.3 运行期锁定

模拟运行期间：

- 中部主区域应显示半透明灰色蒙版。
- 蒙版覆盖左侧菜单和右侧内容区。
- 蒙版不得覆盖顶部标题栏和底部状态栏。
- 蒙版中央必须提供“取消”按钮，作为停止当前模拟的可见入口；除该按钮外，蒙版不显示其他文字、图标或操作。
- 点击“取消”应执行与停止热键相同的安全停止流程，并在停止完成后恢复运行前的 ReadyKeyboard、ReadyMouse 或 ReadyCustom 状态。
- 用户不得切换页面或修改按键、鼠标、自定义序列、热键和提示音设置。
- 后端必须拒绝保存配置、更新热键、坐标拾取、切换页面、驱动安装/卸载、开始录音等会改变运行上下文的操作。
- RunningCustom 必须与 RunningKeyboard、RunningMouse 受到相同的写操作保护。
- 查询状态、检查驱动、读取配置和停止模拟等只读或停止操作应保持可用。
- 停止确认完成后应移除蒙版并恢复界面操作。

录音和坐标拾取期间也应阻止与当前活动冲突的启动、写入和页面切换操作。

## 13. 配置数据与持久化

### 13.1 配置内容

配置应包含：

- 按键动作列表。
- 鼠标动作列表。
- 自定义序列列表。
- 启动热键和停止热键。
- 日志等级。

按键动作至少包含：

- 唯一 ID。
- 启用状态。
- 显示名称。
- scan code。
- 间隔时间。

鼠标动作至少包含：

- 唯一 ID。
- 启用状态。
- 单击类型。
- 可空的 X、Y 坐标。
- 间隔时间。

自定义序列至少包含：

- 唯一 ID。
- 序列名称。
- 有序的键盘/鼠标动作集合。

每个自定义动作至少包含：

- 唯一 ID。
- 启用状态。
- 动作种类及对应参数。
- 动作执行后的间隔时间。

### 13.2 默认配置

首次运行时默认配置为：

| 配置项 | 默认值 |
|---|---|
| 按键动作 | 1 条启用的 F，scan code 33，间隔 20ms |
| 鼠标动作 | 1 条启用的左键单击，坐标为空，间隔 20ms |
| 自定义序列 | 空 |
| 启动热键 | F12，scan code 88 |
| 停止热键 | F12，scan code 88 |
| 默认间隔 | 20ms |
| 最小有效间隔 | 5ms |
| 发布环境日志等级 | Error |
| 开发环境日志等级 | Info |

### 13.3 配置文件

- 应用采用便携模式，配置文件固定为可执行文件同级 data/mimic.ini；不得改写到 AppData。
- 默认配置必须内置于代码，不依赖外部模板文件。
- 每次启动都必须检查配置文件是否存在，并完成文件大小、格式、结构和数值边界校验。
- 配置文件不存在时，应直接使用代码内置默认配置生成新文件。
- 配置文件无法解析、结构不合法或超出限制时，应使用代码内置默认配置直接覆盖，不额外创建备份，也不尝试保留局部字段。
- 配置文件无法创建或写入时，应使用内存默认配置继续启动，并在首页展示初始化警告。
- 旧配置中没有自定义序列数据时，应先按空自定义序列补齐，再执行完整校验，不得仅因此视为损坏。
- 重复的动作 ID 或序列 ID 属于无效配置，应触发默认配置覆盖。
- 配置写入应使用同目录临时文件原子替换，失败时不得破坏原文件。
- 写盘失败时不得把未持久化值当作已保存值。

### 13.4 数据边界

| 数据项 | 上限或范围 |
|---|---|
| 独立按键动作 | 最多 500 条 |
| 独立鼠标动作 | 最多 500 条 |
| 自定义序列 | 最多 100 个 |
| 单个自定义序列动作 | 最多 1000 条 |
| 自定义序列名称 | 最多 64 个 Unicode 字符 |
| 动作间隔 | 5ms 至 3,600,000ms |
| mimic.ini 文件大小 | 最大 5MiB |

- 界面新增或编辑将超过限制时，应拒绝本次操作、保留原数据并显示明确提示。
- 启动时配置超过任一上限或范围时，按无效配置处理并使用代码内置默认配置覆盖。
- 后端必须独立校验所有限制，不得只依赖前端控件。

### 13.5 持久化时机

- 新增、删除、启用/禁用、排序、动作类型变化和坐标拾取等结构性变更应立即持久化。
- 间隔时间和序列名称在失焦或按 Enter 提交时持久化。
- 热键只在用户点击保存且内容发生变化时持久化。
- 提示音只有用户在剪裁完成后点击保存才替换文件。
- 模拟、拾取或录音进行中应拒绝冲突的配置写入。
- 因运行中而被拒绝的自动持久化不应打断当前模拟或反复弹出错误。

## 14. Interception 驱动管理

### 14.1 状态检测

应用启动时应检测驱动状态：

- NotInstalled：驱动未安装。
- InstalledNeedReboot：服务已安装但驱动尚未加载。
- Ready：驱动已加载，热键和模拟可用。
- Error：检测或初始化失败。

- 驱动状态检测不得阻止应用启动。
- 驱动检测失败应记录日志并显示可理解的错误。
- 驱动未就绪时，应明确告知用户模拟和热键不可用。

### 14.2 安装

- 仅 NotInstalled 状态提供安装入口。
- 用户点击安装后，普通权限主程序应启动提权辅助程序并请求 UAC；用户取消或提权失败时不改变驱动状态。
- 提权辅助程序只能执行内置的驱动安装动作，并将结构化结果返回主程序。
- 安装命令成功即进入“已安装待重启”展示。
- 重启前模拟功能保持不可用。
- 驱动安装程序应随应用提供，并位于可执行文件同级的 driver 子目录中。

### 14.3 卸载

- Ready 和 InstalledNeedReboot 状态提供红色“卸载驱动”入口。
- 用户点击卸载时，应先显示内联文字确认区，不得提前触发 UAC。
- 用户必须准确输入“卸载驱动”四个字后才能点击“确认卸载”。
- 用户确认卸载后，普通权限主程序才启动提权辅助程序并请求 UAC。
- 提权辅助程序只能执行内置的驱动卸载动作；用户取消或提权失败时不改变驱动状态。
- 输入不匹配时确认按钮禁用，并显示提示。
- 卸载成功后显示“驱动已卸载，需重启电脑”，并将主要操作切换为“重启电脑”。
- InstalledNeedReboot 状态下，“重启电脑”和“卸载驱动”应同时可见。

### 14.4 重启电脑

- 重启操作必须由用户主动点击。
- 执行前应给用户明确提示，用户确认后才允许通过提权辅助程序请求 UAC 并执行系统重启。
- 用户取消确认、取消 UAC 或提权失败时不得执行系统重启。
- 安装、卸载和重启操作在模拟、录音或坐标拾取期间不得执行。

### 14.5 发布资源完整性

可运行发布包必须包含：

- 可执行文件同级的 Mimic.exe 和 interception.dll。
- driver 子目录中的提权辅助程序和 install-interception.exe。
- data/audio 子目录中的按键开启.wav 和按键关闭.wav 默认提示音。
- 可由应用生成的 data/mimic.ini、data/logs 和 data/temp 可写数据目录。
- Mimic 正式品牌图标资源。

- 可执行资源与可写数据必须按目录逻辑隔离：Mimic.exe、DLL、提权辅助程序和驱动安装器不得放入 data 目录，配置、日志、临时文件和用户提示音不得写入 driver 目录。
- interception.dll、提权辅助程序或驱动安装器缺失时不得生成或交付不完整发布包。
- 提权辅助程序和其调用的驱动安装器在执行前必须通过编译期固化的 SHA-256 强哈希校验；校验失败时拒绝提权执行。
- 默认提示音必须是可正常播放的 PCM WAV。
- 关键资源复制、打包或完整性检查失败时，发布构建应明确失败，不得只输出警告后继续交付。

## 15. 热键提示音

### 15.1 文件

- 启动提示音路径为可执行文件同级 data/audio/按键开启.wav。
- 停止提示音路径为可执行文件同级 data/audio/按键关闭.wav。
- 中文文件名不得改为 ASCII 别名。
- 提示音必须为 PCM WAV。
- 两个提示音应使用兼容的音频格式。
- 文件缺失、损坏、格式不支持或两文件格式不兼容时，应静默跳过对应声音，不影响模拟。
- 发布包应提供可直接使用的默认启动和停止提示音。
- 用户可以直接替换 data/audio 目录中的提示音文件；外部替换的文件最迟在下次启动时重新加载。

### 15.2 播放规则

- 启动热键真正启动模拟时播放启动提示音。
- 停止热键真正停止模拟时播放停止提示音。
- 被忽略的热键不得播放提示音。
- 启动键与停止键相同时，应根据本次实际行为播放对应声音。
- 新提示音触发时，应立即打断尚未播放完的旧提示音。
- 提示音播放必须异步，不得阻塞热键监听、模拟执行或界面。
- 应用启动后必须在后台静默加载两个 WAV 到内存，并提前完成 WAV 解析、音频输出设备初始化、播放缓冲区准备等触发播放前可完成的工作。
- 热键触发和“试听”的实时路径不得读取磁盘、解析 WAV、打开音频设备或执行其他可提前完成的初始化，应直接使用已准备的内存资源并尽快输出。
- 音频资源尚未准备完成或初始化失败时，不得阻塞或延迟模拟；本次声音可跳过，并记录符合当前日志等级的诊断信息。
- 录音保存只有在新文件写入、校验、内存加载和播放准备全部成功后才算成功；成功后的下一次热键触发或试听必须播放新文件，无需重启应用。
- 当前版本只支持 PCM WAV，不提供格式转换、重采样或其他复杂兼容处理；不支持或不兼容的文件应跳过播放且不影响模拟。

## 16. 提示音录制与剪裁

### 16.1 设置页入口

设置页“提示音”区块应分别展示：

- 启动提示音。
- 停止提示音。

每一项应包含：

- 已录制/未录制/面板展开中的状态标识。
- 状态文字。
- “试听”按钮。
- “录制”按钮。

- 试听和录制按钮组宽度为 140px，与上方输入框对齐。
- 展开某一项录制面板期间，应禁用另一项的录制和试听。
- 点击“录制”只展开面板，不立即开始采集。
- 面板展开后应自动滚动到完整可见位置。

### 16.2 录音

- 录音使用系统默认麦克风。
- 不提供设备选择。
- 最大录音时长为 5 秒，到时自动停止。
- 面板未开始录音时，波形区域显示居中横线。
- 用户点击“开始录制”后才开始采集。
- 录音中显示实时波形和“当前时长 / 5 秒”倒计时。
- 用户可以点击“结束录制”提前停止。
- 录音完成后不得立即写盘，应进入剪裁状态。
- 剪裁状态下再次点击“开始录制”应丢弃当前缓冲并重新录音。
- 保存的提示音应为单声道、16-bit PCM WAV；采样率可以使用输入设备支持的有效采样率。

### 16.3 剪裁

- 录音结束后展示完整静态波形。
- 波形上应提供可拖动的开始和结束标记。
- 初始选区覆盖完整录音。
- 最短选区为 100ms。
- 选区外区域应使用半透明遮罩。
- 界面应实时显示选区起止时间和选区时长。
- 选区标记使用橙色等强调色。
- 用户点击“试听”时只播放选区，不修改文件。
- 试听时应显示与播放位置同步的进度线。
- 试听进度线应使用与选区标记不同的颜色。

### 16.4 保存与取消

- 点击“保存”后，只将选区内容写入对应的启动或停止提示音文件。
- 写入前应停止当前正在播放的提示音。
- 写入应先生成临时文件，再原子替换目标文件。
- 写入失败时旧提示音文件必须保持不变。
- 写入成功后应立即刷新播放内容并关闭面板。
- 点击“取消”应丢弃录音缓冲、关闭面板且不修改文件。
- 录音过程中点击取消，应先安全停止采集，再关闭面板。
- 离开设置页时应自动取消尚未完成的录音。
- 关闭应用时应停止录音并丢弃未保存缓冲，不产生不完整文件。

### 16.5 状态与错误

- 录音采集期间状态栏显示 Recording 或“正在录制提示音”。
- 录音期间不得启动模拟、拾取坐标、切换页面或保存冲突配置。
- 模拟或坐标拾取期间不得开始录音。
- 未检测到麦克风时，录制按钮应禁用并显示“未检测到麦克风”。
- 麦克风被占用、权限被拒绝或初始化失败时，应显示错误并恢复可操作状态。
- 写盘失败应显示错误，但不得影响其他功能或原提示音。

## 17. 日志、错误与降级

### 17.1 日志

- 后端应记录足够信息以排查配置、权限、驱动、热键、模拟和音频问题。
- 发布环境首次启动默认仅记录 Error 及以上级别；开发环境默认记录 Info 及以上级别。
- 设置页应提供 Error、Warn、Info、Debug 四档日志等级；用户修改后必须持久化，并在后续启动恢复。
- 日志等级修改应在当前进程即时生效，不要求重启应用；等级切换本身应记入新等级允许的日志。
- 发布环境日志写入可执行文件同级 data/logs，开发环境可同时输出到标准输出。
- 文件日志应按大小轮转：单个文件最大 5MiB，最多保留当前文件和 3 个历史文件；轮转或写入失败不得导致应用崩溃。
- 日志不得记录与应用无关的原始键鼠输入、录音音频内容、热键之外的完整输入轨迹、凭据或不必要的绝对用户路径。
- 日志至少覆盖：
  - 应用启动、配置校验及默认配置覆盖结果。
  - 提权请求结果，以及驱动检测、安装、卸载和重启操作。
  - 热键配置更新、冲突、去抖和监听异常。
  - 模拟启动、停止、停止耗时和执行错误。
  - 配置读写及持久化错误。
  - 提示音预加载、播放、录音和保存错误。

### 17.2 错误反馈

- 用户可恢复的错误必须以中文可理解信息显示。
- 高权限不足、运行中冲突、持久化失败、热键冲突、驱动不可用、麦克风不可用和音频写入失败应可区分。
- 关键错误应同时记录日志。
- 错误提示不得泄露不必要的敏感路径或内部细节。
- 驱动、麦克风或提示音不可用不得导致整个应用崩溃。
- 配置加载失败不得阻止界面打开。
- 无效外部文件和畸形 WAV 不得导致应用崩溃。
- 后台任务发生错误后，应用必须恢复到可理解、可继续操作或可重试的状态。

### 17.3 错误后的最终状态

错误恢复采用分层规则：

- 输入驱动、全局监听器或 Runtime 发生关键错误时，必须立即停止当前模拟、尽力释放全部由应用按下的键盘键和鼠标按钮，并进入 Error 状态。
- 关键错误发生后不得自动显示为 Ready。只有错误来源重新检测或重新初始化成功后，才能根据当前页面恢复为 ReadyKeyboard、ReadyMouse、ReadyCustom 或 Idle。
- 如果输入释放未完全成功，必须保持 Error 状态，记录每个释放失败项，并提示用户停止相关操作或重新插拔设备后重试。
- 配置保存、坐标拾取、录音、提示音保存等局部操作失败时，应回滚本次操作，恢复操作前的内存数据、持久化数据和 Ready/Idle 状态，并显示可重试错误；不得因局部失败进入全局 Error。
- 配置保存失败时，界面必须恢复为最后一次成功持久化的值；坐标拾取失败时保留原坐标；录音或提示音保存失败时保留原提示音文件和原内存播放资源。
- 提示音预加载、试听或运行期播放失败属于可选功能降级：本次声音应跳过并记录日志，键鼠模拟继续执行，整体状态不得进入 Error。
- 多个错误同时发生时，以安全等级最高的结果为准；任何输入驱动、监听器或 Runtime 关键错误都优先进入 Error。
- 状态恢复、数据回滚和错误提示必须作为同一恢复流程完成，避免前端状态、Runtime 快照和磁盘数据彼此不一致。

## 18. 安全、可靠性与性能要求

### 18.1 安全

- 普通应用功能不得要求管理员权限，主程序不得因维护驱动而整体提权。
- 高权限操作必须由用户显式发起，只能通过最小权限辅助程序执行预定义操作，并校验被执行资源的编译期固化 SHA-256 强哈希。
- 应用不得执行用户未确认的安装、卸载或系统重启。
- 所有来自界面和配置文件的路径、数值、类型和长度应进行有效性校验。
- 应用保持整目录便携，但必须使用 data 子目录隔离全部可写用户数据；可执行文件、DLL、提权辅助程序和驱动安装器不得写入 data。
- 配置、日志、临时文件和提示音目标不得越出各自规定目录；路径校验应使用规范化后的绝对路径并防止路径穿越。
- 便携目录整体仍可能被当前用户修改，因此每次高权限执行前必须重新校验提权辅助程序和驱动安装器完整性，不能把目录隔离等同于操作系统权限隔离。
- 运行期交互锁定必须同时由界面和后端约束，不能只依赖蒙版。
- 可执行文件、驱动安装器、动态库和音频资源应从预期目录加载。
- 应用不得静默执行无法确认来源的系统命令或可执行文件。

### 18.2 可靠性

- 配置写入应保持内存与磁盘状态一致。
- 模拟、录音、坐标拾取和驱动维护应互斥，不能相互串台。
- 每次模拟只能作用于启动时选定的页面或自定义序列。
- 停止、错误或退出后不得留下持续按下的键盘键或鼠标按钮。
- 应用退出时应停止所有后台活动并释放驱动、录音和音频资源。
- 重复启动、停止、录音和拾取不得产生重复会话或僵尸任务。
- 用户输入事件在不属于应用热键或拾取目标时应正常透传。

### 18.3 性能与响应

- 热键监听和键鼠模拟不得阻塞界面线程。
- 提示音播放应使用启动后后台预加载并准备完成的内存资源；具体听感延迟由验收测试判断，不设固定 15ms 门槛。
- 停止请求应满足第 11.4 节的 P95 100ms、最坏 250ms 指标，包括动作间长延时期间。
- 页面切换、列表编辑和滚动应保持流畅。
- 录音实时波形应平滑更新，不得明显影响录音采集。
- 配置不得在用户逐字符输入时频繁写盘。

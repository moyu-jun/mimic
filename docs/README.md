## 当前文档

### [ARCHITECTURE.md](./ARCHITECTURE.md) — 模拟模块架构设计（v2.0）

**最后更新**: 2026-07-24

**内容概要**:
- **需求概述**: 键盘/鼠标模拟功能需求，包括按键、长按、点击、滚轮、混合序列等
- **设计目标**: 高内聚低耦合的模拟模块架构
- **核心模块**:
  - 统一事件模型（`SimulationEvent`）
  - 动作定义（`KeyAction`、`MouseAction`、`ActionSequence`）
  - 驱动抽象层（`InputDriver` trait）
  - Interception 驱动实现
  - Worker 线程（事件消费者）
  - 执行器（序列调度器）
- **方案选择**: 方案 B（双线程 + 统一延迟），时序精确且扩展性好
- **实施计划**: 分 4 个阶段渐进式重构

**适用场景**: 开发人员理解模拟模块设计、实施重构、扩展新功能

## 文档说明

### 文档生命周期

1. **当前文档**（`docs/` 根目录）
   - 反映当前或即将实施的设计
   - 开发时的主要参考
   - 保持最新状态

2. **归档文档**（`docs/archive/`）
   - 已完成阶段的历史记录
   - 追溯决策和演进过程
   - 只读，不再更新

### 如何使用

- **开始新功能开发**: 阅读 `ARCHITECTURE.md` 了解模块设计
- **理解现有代码**: 对照归档文档和代码，了解实现历史
- **追溯设计决策**: 查看 `archive/CHANGELOG.md` 和 Git 提交记录

## 贡献指南

### 更新文档

当实施重大变更时：
1. 如果是新阶段：创建新的设计文档（如 `ARCHITECTURE_V3.md`）
2. 如果是渐进迭代：更新现有 `ARCHITECTURE.md`
3. 完成后：将过时文档移至 `archive/`，并在本 README 更新索引

### 文档规范

- **架构文档**: 包含需求、设计、实施计划、验收标准
- **变更日志**: 记录实施过程中的关键决策和偏差
- **代码注释**: 复杂逻辑在代码中注释，文档侧重宏观设计
